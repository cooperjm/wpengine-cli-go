How should sites and environments be displayed?

Three approaches to make prod/stg/dev easier to read at a glance.

A

Grouped rows — site as header, envs indented below

Each site gets a bold header row, with its prod/stg/dev environments listed beneath it with indentation. One row per environment, clearly nested under the parent site.

wpengine site list
⬡ acme-corp uuid-1234
PROD acme-production acme-production.wpengine.com
STG acme-staging acme-staging.wpengine.com
DEV acme-dev acme-dev.wpengine.com
⬡ globex-wp uuid-5678
└─ PROD   globex-wp   globex-wp.wpengine.com
B

Stacked env badges in the Environments column

Keep the current table structure but replace the comma-joined string with stacked lines — one line per environment, each with a colored badge. Much easier to scan than a run-on string.

wpengine site list
NameEnvironmentsAccount
acme-corp
PROD acme-production
STG acme-staging
DEV acme-dev
 acc-abc
globex-wp
PROD globex-wp
 acc-def
C

Flat table grouped by environment type

A single flat table (like env list) but with environments sorted and visually sectioned: all PROD first, then STG, then DEV. Clear dividers and count per section.
